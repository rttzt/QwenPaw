- **核心入口**：`DingTalkChannel` 继承自 `BaseChannel`，通过 `start()` 初始化 `dingtalk_stream.DingTalkStreamClient` 并在独立线程中运行 WebSocket 监听循环。
- **请求处理链路**：`DingTalkChannelHandler` 作为 SDK 回调处理器，将钉钉原生消息转换为内部 Native Payload，经去重与防抖后入队，由基类消费循环调用 `_process_dingtalk_core` 驱动 Agent 执行。
- **回复策略分支**：根据配置动态选择回复通道——优先使用 `sessionWebhook` 实现多消息分片发送；若启用 AI 卡片模板则通过 `card_1_0` SDK 创建并流式更新 `ActiveAICard`；在 Webhook 失效时自动降级至 `robot_1_0` Open API 推送。
- **持久化与恢复**：利用 `AICardPendingStore` 和 JSON 文件持久化活跃卡片与会话 Webhook 映射，支持服务重启后的状态恢复与过期清理。
