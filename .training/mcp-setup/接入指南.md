# MCP Mock Server 接入指南（学员版）

> 本指南只讲学员现场要做的事：把讲师统一部署的 MCP mock server 登记到你的 QwenPaw default Agent。
>
> 完整原理（C8/C10 翻车点诊断）见 M3 课堂复盘环节。

## 讲师 Mock Server 信息

| 项 | 值 |
|---|---|
| URL | `http://47.96.133.214:9876/mcp` |
| 协议 | streamable HTTP |
| 鉴权 | 无 |
| 提供工具 | `get_customer_profile` / `get_industry_cases` / `search_customer` / `health_check` |

> 培训当天若 IP 有变，讲师会在钉钉群通知。

## 一行命令接入

```bash
# 在 QwenPaw 仓库根目录执行
python3 .training/mcp-setup/add_presales_mock_to_agent.py \
    --url http://47.96.133.214:9876/mcp
```

成功标志：

```
✅ presales_mock 已加入 ~/.qwenpaw/workspaces/default/agent.json
   现有 clients: ['tavily_search', 'qoder_bridge', 'presales_mock']
```

> 脚本是**幂等**的，多次执行结果相同；自动备份 `agent.json.bak`。

## 验证接入成功

`qwenpaw app` 终端日志会在 1-5 秒内出现：

```
MCP client connected: presales_mock
```

## 常见问题

### Q1：脚本说 `working_dir not found`？

QwenPaw 工作目录优先级：`QWENPAW_WORKING_DIR` env > `~/.copaw`（旧版）> `~/.qwenpaw`（默认）。

确认 `qwenpaw app` 至少启动过一次，会自动建好工作目录。

### Q2：日志里没出现 `MCP client connected: presales_mock`？

可能 mock server 临时断网。验证讲师 server 是否存活：

```bash
curl -m 3 -X POST http://47.96.133.214:9876/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","method":"initialize","id":1,"params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"smoke","version":"1"}}}'
```

返回 `event: message` + JSON 即可达。如不通请联系助教。

### Q3：跑完脚本但 Bot 输出说"没有 MCP 服务器"？

去 `qwenpaw app` 终端看日志，没看到 `MCP client connected: presales_mock` 就是没接上。检查 `agent.json` 里的 `presales_mock.url` 是否为讲师当前 IP。

### Q4：要回滚？

```bash
python3 .training/mcp-setup/add_presales_mock_to_agent.py --remove
```

## 为什么这一步是必须的（C8 / C10 翻车点）

仅启动 mock server **不够**。QwenPaw 的 `MCPClientManager` 只连接登记到**当前 Agent 配置**的 client。跳过这一步 →  LLM 拿不到 mock 数据 → 输出会被被动降级为"靠通识编造"。

这是 M3 课堂上"看似详细的 prompt 直接交给 Qoder 也会翻车"的两个真实根因之一。
